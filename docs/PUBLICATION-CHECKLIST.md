# 공개 체크리스트

## 현재 판정

원본 저장소는 그대로 공개하면 안 됩니다. 실제 시험 데이터, 로그, 회사 식별자, 내부 네트워크 정보와 인증 관련 설정이 포함되어 있습니다.

## 반드시 제외

- 실제 시험 패키지, 답안, 사용자·감독 데이터와 촬영 파일
- 애플리케이션 로그와 오류 추적 정보
- 회사명, 고객명, 사내 도메인, 이메일과 저장소 주소
- 내부 IP, 포트 구성, 데이터베이스 이름과 스키마
- 비밀번호, 토큰, JWT 비밀키, 인증서와 API 키
- 운영용 Docker Compose, 환경 설정과 배포 정보
- 원본 `.git` 이력과 다른 작업자의 이름·이메일
- 회사 전용 정적 리소스, UI 자산과 문서

## 공개 방식

1. README 중심의 아키텍처 사례를 먼저 공개합니다.
2. 코드가 필요하면 원본에서 복사하지 않고 일반화된 요구사항으로 새로 구현합니다.
3. 샘플 데이터는 임의 생성하고 실제 식별자 형식을 재사용하지 않습니다.
4. 새 저장소에는 깨끗한 Git 이력만 생성합니다.
5. 비공개 저장소에서 검토한 뒤 공개 상태로 전환합니다.

## 공개 직전 검사

- 비밀정보 탐지 도구 실행
- 회사·고객 식별자 전체 검색
- 내부 주소·이메일·사용자 데이터 검색
- 이미지와 압축 파일 수동 검토
- 라이선스와 제3자 소스 확인
- 본인 기여 표현과 공동 작업 범위 확인
- 회사의 공개 정책 또는 승인 여부 확인
