# 기여 내역

## 산정 기준

- 로컬에 보관된 각 Git 저장소의 전체 브랜치 이력을 기준으로 작성자를 집계했습니다.
- 사용자가 본인 계정임을 확인한 Git 작성자를 기준으로 집계했습니다. 실제 계정명은 공개 문서에서 제외합니다.
- 커밋 수는 작업량이나 품질을 직접 의미하지 않으며, 담당 범위를 찾기 위한 보조 근거로만 사용합니다.

## 포트폴리오에서 강조할 내용

1. 동기 API와 비동기 이벤트 처리를 함께 사용한 이유
2. Redis와 PostgreSQL의 데이터 책임을 구분한 기준
3. Gateway와 인증 서비스 사이의 JWT·토큰 상태 검증 흐름
4. 공통 도메인 라이브러리 버전 변경을 여러 서비스에 전파한 방식
5. 메시지 처리 실패 시 데이터 유실을 줄이기 위한 저장 흐름

## 추가 확인이 필요한 내용

- 공동 작업 중 본인이 설계까지 담당한 영역과 구현만 담당한 영역
- 공개 가능한 정량 지표가 있는지
- 회사의 외부 공개 승인을 받았는지
