# 근거와 공개 예제 구분

Git 커밋과 파일별 변경 구간을 대조하여 본인 수정 범위를 확인하였습니다. 공통 코드에는 다른 개발자의 변경도 존재합니다. monitor·proctor는 확인한 로컬 Git 이력에서 본인 커밋이 없으며, websocket은 공통 의존성과 설정 변경만 담당 범위에 포함하였습니다.

## 확인 결과

| 기능 | 원본에서 확인한 내용 | 공개 예제의 보완 또는 확인 한계 |
|---|---|---|
| 응시자 설정·답안 요청 | 이중 직렬화 목록 변환과 data 내부 답안 해석 변경 | 문자열 원소 제한, 필수 객체 명시 검증, 읽기 전용 결과 |
| 워커 저장 | Redis 저장 시도 후 DB 작업을 연결하는 순서 변경 | EventProcessor의 이벤트 ID 멱등성 저장소·실패 큐는 추가 설계 |
| 최근 로그 | 최신 로그 앞쪽 추가와 보존 개수 정리 | 설정 가능한 보존 개수, 양수 만료시간 검사 |
| 파일 반입 | ZIP·JSON 시험자료 처리 기능 | 경로 이탈 차단·필수 파일 검증은 공개 반입 예제의 보완 |
| 인증·감독 데이터 | 토큰·Redis 상태 확인, 응시자 이벤트 처리 | 분리한 인증 인터페이스와 이벤트 ID 중복 방지 규칙 전체를 과거 구현으로 간주하지 않음 |

## 공개 코드의 역할

공개 코드는 원본의 업무 흐름을 설명하기 위해 독립 작성하였습니다. 회사 소스·쿼리·실제 식별자·내부 주소·인증정보·업무 데이터를 포함하지 않습니다. 별도 설계 규칙이 포함된 기존 예제도 유지하되 실제 재직 중 구현한 사실과 구분하였습니다.

신규 사례의 입력·처리·예외는 [구현 사례 상세](CASE-STUDIES.md), 실행 범위는 [검증 결과](VALIDATION.md)에 정리하였습니다. 테스트는 공개 예제의 로직과 가짜 저장소 계약에 한정되며 회사 원본 시스템, 실제 DB·메시지 큐·기관 SSO·LLM 서버의 통합 검증 결과가 아닙니다.
